## 背景

公開リポジトリでの漏洩リスクとして、ローカルの `pre-commit` フックでの `detect-secrets` スキャンを `--no-verify` などでバイパスして、高エントロピーなシークレットがプッシュされてしまうギャップがありました。これを CI でも検知してブロックする必要があります。

## このPRで導入するもの

- ツール名: detect-secrets v1.5.0
- 導入箇所: `.github/workflows/detect-secrets.yml`
- 期待される効果: GitHub への push / PR および定期実行時にベースラインに対して detect-secrets のスキャンを行い、新たな高エントロピーのシークレットが混入していればブロックする。

## 検知漏れリスクと補完策

- 検知できないケース: detect-secrets の検知器やフィルタの除外対象となるシークレットは、検知できない場合がある。
- 補完策: 既存の `gitleaks` (CI および pre-push)、`trufflehog` ワークフロー、GitHub Secret Scanning や Push Protection を組み合わせて多重防御を実施済み。

## マージ前に必要な手動作業（チェックリスト）

レビュアーは PR をマージする前に必ず以下を実施してください。
本 PR の CI は手動作業完了を前提に通る設計です。

- [ ] リポジトリの設定で、`Push Protection` と `Secret Scanning` が引き続き有効になっていることを確認する。
- [ ] 開発チーム全体に、偽陽性時は `bun run detect-secrets:update` を用いてローカルのベースラインを更新・コミットする運用であることを再周知する。

## マージ後の確認手順

- [ ] 本PRのマージ後の push において、`.github/workflows/detect-secrets.yml` が green になることを確認する。
- [ ] PR 内で誤検知（False Positives）が出た場合、ローカルでのベースライン更新運用が機能するかを確認する。

## ロールバック手順

問題が出た場合や CI 実行時間に深刻な影響があった場合は、`.github/workflows/detect-secrets.yml` を削除または disable にし、変更前の状態に revert してください。
