## 2025-02-12 - In-Memory Rate Limit Cache Flooding
**Vulnerability:** A Denial of Service (DoS) vulnerability existed in the in-memory rate limiting mechanism for the contact route. Attackers could flood the cache with new IP addresses until the `MAX_BUCKETS` limit was reached. Upon reaching the limit, the system blindly deleted the oldest inserted key to make room, potentially evicting active rate-limited IP addresses and allowing attackers to bypass the rate limit.
**Learning:** This occurred because the cache eviction logic prioritized simplistic garbage collection over scanning for genuinely expired entries. When protecting shared resources, maintaining the state of blocked entities takes precedence over new, potentially malicious entries.
**Prevention:** When enforcing maximum size limits on in-memory caches (e.g., `Map` objects for rate limiting), always scan and evict expired entries first before evicting the oldest key. This ensures attackers cannot maliciously fill the cache to push out their own active tracking entries.
